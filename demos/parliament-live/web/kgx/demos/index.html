Network views (#defaultView:Graph)

Force-directed graph rendering. Convention: rows have ?source and ?target (URIs) plus optional ?sourceLabel / ?targetLabel / ?edgeLabel / ?sourceImage / ?targetImage. Nodes dedupe across rows automatically.

Multi-endpoint federation (experimental)

Real SPARQL federation: our endpoint calls out to a remote one via the SERVICE keyword. Powerful in theory; in practice the optimiser doesn't always push bindings into the remote call, so anything beyond a hand-pinned entity tends to time out at ~30 s. Try it on a single entity first.

Oxigraph 0.5's federation works for SERVICE-with-pinned-URI; joins with several bindings often hit fly.io's 60 s edge timeout. If a federation query 502s, the data is fine — just rewrite to pass one entity at a time and aggregate client-side.

UK flag + capital, via federation to Wikidata

federationfpkgwikidataimage

Local store knows our country URI ↔ Wikidata Q145. The SERVICE clause pulls the flag image + capital name from Wikidata at query time. Single pinned entity → reliable ~1 s.

UK PMs joined to DBpedia abstracts via SERVICE

federationwikidatadbpediaimage-grid

Two SPARQL endpoints, joined by the SPARQL Protocol: query starts on Wikidata, the SERVICE <https://dbpedia.org/sparql> clause sends each PM's DBpedia URI to DBpedia and pulls back its English abstract. The #defaultView:ImageGrid directive flips the playground to thumbnail mode.
